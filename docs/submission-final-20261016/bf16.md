# Qwen3.8-27B / BW100 / SGLang / BF16 性能报告

## 一、测试环境

单机两张 BW100，物理 DCU2/3，IFB TP2，slots32；卡型/驱动/镜像声明见 env_declare.yaml，驱动 6.3.30-V1.4.1a，SGLang 0.5.12，DTK 26.04 镜像。模型路径 `/data/zk/qwen38/model`，模型配置 SHA256 `191e0af232104ed8b65258cf3fb2b842e288008baca7633c11b82a1ac7203aab`（只对应配置，不代表全部权重分片已验真）。权重为官方 BF16。BF16 KV，FP32 SSM，原版 GEMM，禁用 custom all-reduce。

## 二、Baseline 与统计口径

固定场景输出吞吐均指实际输出 token/s，双卡总值除 2 为单卡值。工作 SLA：4K mean TTFT <5s 且 mean TPOT <50ms；64K <20s 且 <60ms，p95 保留在原始结果中。按用户提供主办方回复采用均值口径。

全档使用两轮预热、单轮正式；正式每轮 max(8,2C) 请求。关键边界另测三轮，报告三轮全部结果及平均，不用单轮最好值替代平均。2026-10-16 已决定封存现有数据、不再补跑。该轮数与官方教程全档三轮的建议存在差异，如实披露，是否认可由评审决定。

4K SLA 内峰值参考分母为官方固定档表中按均值重算通过的 C8：182.734/2=91.367 tok/s/卡；64K 为 C1：13.616/2=6.808。官方另表列 4K 最大并发 C1，与固定档均值表冲突；本报告清楚采用 C8 重算口径，比例为算术对比，不冒称已确认官方得分。两精度都列相对官方 BF16 的同一分母；这与同 INT8 权重调参收益是两个指标。

## 三、优化方法

FA3 用于注意力路径；HCU KV layout 和连续 FA 用于布局/访存路径；EAGLE 3 步、topk1、4 draft tokens 用于减少 decode 的目标模型串行步骤，收益依赖接受率。槽位数控制并发状态预留与 KV 容量的取舍。统一配置为 `fa3_hcu_contigfa_eagle314_slots32_no_custom_ar`。以上作用机制是优化动机，组合性能以实测为准，未以理论解释代替单因素归因。

本方案 FA3、KV 布局、连续 FA、EAGLE、槽位为组合优化，报告不把组合总收益冒归单一开关。

未采用 PD、DP、多于两卡、FP8 KV、NEXTN 或 SGLang 0.5.18。NN GEMM 因长输入回退且未做对应最终精度验证，不纳入提交。

## 五、适用范围与取舍

两种精度各自采用统一服务配置，适用于本记录的 BW100/适配镜像。推测解码效果随数据与接受率变化；槽位提高会增加 SSM 状态预留、挤占 KV。吞吐不能替代 TTFT/TPOT，尤其高并发 ShareGPT 的时延。

不同日期启动脚本 SHA 有变化，包内按哈希提供历史原件；不把跨日期数据说成同一次 uptime。BF16 的 F029 C8 是已终止的部分运行，保留日志但不计成绩。关键复测批次曾被显存释放延迟的占用保护拒绝，原 status=1 与后续恢复 status=0 均保留。原始日志不拼接、不改写；结果索引与文件哈希见 result/ 和 FILES.sha256。

提交保留的限制：全档/ShareGPT 为单轮、边界为三轮；仅 GSM8K 已测；ShareGPT 文件身份和最终评审分母/聚合口径待确认；未录制演示视频。Demo 启动和访问脚本已提供，但本次整理没有启动模型或录制新 Demo。
